Ballast Control Process Simulator

Pump and valve commands, translated into physical tank-level change over time — the same control loop behind a real ballast control system.

← Back to Simulator Suite ← Course Navigation

A ballast control system doesn't move water directly — it issues commands (open a valve, start a pump) that a physical process then carries out over time, changing a tank's fill level and, with it, the vessel's stability. This simulator pairs with Lesson 3, where the ballast control loop is introduced as a representative shipboard OT process: sensors report tank level, an operator or controller issues a command, and an actuator (pump or valve) physically executes it.

Below, you control two simulated ballast tanks. Each pump command only has an effect if that tank's valve is open first — a small, real lesson about interlocks: a command sent to a closed valve is not a command that gets carried out.

What this teaches

This mirrors the real ballast control loop discussed in Lesson 3: a command (pump on, valve open) is only meaningful once it is physically carried out, and interlocks like the valve requirement exist precisely because a control system's commands are instructions to physical equipment, not just software state. The vulnerabilities and threats lessons cover how an attacker who gains write access to this same command path — without ever touching a valve by hand — could pump ballast unevenly and destabilize a vessel's trim or list. Lesson 7's network segmentation countermeasures exist specifically to keep that command path reachable only by authorized control-system traffic, not by anything that happens to be on the same converged network.
